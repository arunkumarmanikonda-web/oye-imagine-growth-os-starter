# Oye !magine AI Evolution Engine

Status: expanded master product scope
Date: 14 August 2026

## 1. Product ambition

Oye !magine is to operate as a continuously learning digital Growth OS, not as a collection of disconnected AI generators. Every eligible interaction, generation, execution and measured business outcome must improve the next decision.

The product ambition is deliberately larger than a conventional digital marketing SaaS product: build the digital marketing intelligence layer that becomes better as more brands use it, while protecting each client's confidential data and enforcing commercial, security and legal controls.

The operating loop is:

**observe -> understand -> research -> generate -> evaluate -> execute -> measure -> learn -> improve -> regenerate**

This loop applies to brand intelligence, strategy, copy, image creative, video, landing pages, SEO, keywords, paid media, organic social, lifecycle messaging, analytics, marketplace delivery, CMS operations and platform configuration.

## 2. Every useful activity becomes evidence

The Evolution Engine records structured learning events for at least:

- tenant and workspace signup
- brand facts and brand-story discovery
- website, catalogue, document and competitor research
- every strategy generation and strategy revision
- prompt template, version, provider/model and encrypted runtime prompt lineage
- every copy, image, video, landing page and campaign asset generation
- every human edit, approval, rejection and regeneration
- keyword discovery, recommendation, activation and bid change
- campaign creation, pause, optimization and experiment
- social page, post, reel and story creation or publication
- SEO, AEO and GEO recommendations and measured search visibility
- CRM, email, SMS and WhatsApp journeys where consent permits
- conversions, revenue, lead quality, CPA, ROAS, CTR, CVR and retention
- customer feedback, operator feedback and system quality evaluations
- marketplace specialist outcomes
- failures, rollbacks and rejected recommendations

Generation volume is not itself learning. The system learns primarily from measurable outcomes, user corrections, controlled experiments, brand-fit evaluations and downstream commercial results.

## 3. Prompt memory and lineage

Every generation must be reproducible. Oye !magine stores the prompt template identity, template version, model/provider route, input context fingerprint, output artifact reference and prompt hash.

Where the runtime prompt itself must be retained, it is encrypted before persistence. Raw prompts are tenant-private by default. Personal data, client secrets, private commercial information and regulated content may never be promoted into cross-client memory.

A strong prompt that works for one client may help another client, but the system reuses the abstracted pattern, not another client's confidential prompt or data. Reusable patterns therefore contain learned instructions, structural features, audience/vertical/channel context and outcome evidence after privacy classification and anonymization.

## 4. Two memories, one intelligence system

### 4.1 Private brand memory

Each client receives a persistent tenant and workspace memory containing its brand story, products, audience, tone, vocabulary, prohibited claims, visual identity, offers, competitors, channel history, prior outputs, approvals and performance.

This memory is the source of truth for brand-specific generation and remains tenant isolated.

### 4.2 Oye platform intelligence

The platform intelligence layer contains only reusable, privacy-safe patterns that have passed promotion rules. It can learn that a particular creative structure, prompt architecture, landing-page element, message sequence, keyword cluster or campaign tactic repeatedly produced better outcomes in a comparable context.

Cross-client intelligence requires anonymized reusable scope, no personal or confidential data, sufficient sample size, multi-tenant evidence, confidence threshold, positive outcome evidence and risk checks.

The result is compounding intelligence without tenant leakage.

## 5. Evolution and promotion pipeline

The autonomous learning pipeline is:

1. Capture the activity as a structured event.
2. Classify sensitivity, PII, secrets, tenant and workspace ownership.
3. Attach the exact prompt/artifact lineage where relevant.
4. Correlate delayed outcomes and business KPIs.
5. Normalize and score evidence.
6. Detect repeat patterns by product, category, vertical, audience, channel, language and objective.
7. Distill reusable patterns without copying protected client material.
8. Run quality, privacy, security, brand-fit and adversarial evaluations.
9. Compare candidate against current baseline through controlled experimentation.
10. Promote safe low/medium-risk improvements automatically when thresholds pass.
11. Canary new prompt/routing/workflow behavior.
12. Monitor drift and business impact.
13. Roll back automatically when regression thresholds are breached.
14. Retain full evaluation and promotion history.

The platform must be able to learn that yesterday's best answer is no longer today's best answer.

## 6. Autonomous does not mean uncontrolled

The target experience is near-zero human intervention for normal growth work. Oye !magine can autonomously regenerate drafts, improve prompts, route AI providers, run research, produce strategies, generate assets, optimize inside approved campaign envelopes, pause poor-performing assets and publish content that is covered by explicit pre-approval.

The system must not silently increase a client's budget ceiling, sign a contract for a client, execute an unauthorized payment, rewrite an approved legal template, weaken a security guardrail, apply an untested database migration or push unverified code directly to production.

For those actions, AI may diagnose, propose, generate, test and prepare the change automatically, but the existing governance/release/authorization control remains the final gate.

This distinction is part of the product, not a limitation. A world-class autonomous system is trusted because it knows the boundaries within which it can act without asking.

## 7. Research before recommendation

A user may give Oye !magine an incomplete, unusual or incorrect idea in one sentence. The system should not merely obey the wording.

The workflow is:

**understand intent -> identify missing facts -> research current reality -> compare evidence -> challenge the premise when necessary -> recommend the better route -> generate the work -> measure it**

Research must record source, retrieval date, freshness policy, source quality, supporting and contradictory evidence and confidence. Current-market, platform-policy, competitive, pricing, search, ad-tech and trend assertions should be refreshed according to their volatility rather than treated as permanent memory.

If evidence contradicts the user's proposed approach, the product should explain this in simple language and offer the stronger evidence-backed alternative.

## 8. AI global search and command layer

Oye !magine should have one universal AI search/command experience available across authorized dashboards. The user should not need to understand the internal information architecture.

Examples:

- "Where do I change the homepage hero image?"
- "Mujhe Instagram ke liye premium festive campaign banana hai."
- "Why is Google Ads spend high this week?"
- "Take me to the approval for this campaign."
- "Change this CTA everywhere after approval."
- "What is the best strategy for this product today? Research first."
- "Is this idea actually right for my brand?"

The search layer spans CMS, configuration, brand memory, integrations, strategy, creative, campaigns, social, SEO, analytics, commercial operations, marketplace and support.

Every search result is role, tenant and workspace scoped. Navigation can deep-link the user to the correct configuration. Mutating commands pass through the same permission, approval and autonomy policies as manual actions.

## 9. CMS is the content control plane

All customer-facing editorial and marketing content and media should be controlled through the CMS rather than hardcoded across pages. This includes headings, paragraphs, CTAs, FAQs, cards, proof blocks, imagery, video references, alt text, promotional content and localized variants.

Content nodes are versioned by route, surface, slot, locale and scope. AI edits create version history and prompt lineage exactly like human edits. Published changes remain reversible.

Internal machine errors, security messages and certain fixed engineering constants remain code-controlled where that is safer. The requirement is not to turn security logic into editable marketing content.

## 10. English, Hindi and Hinglish

India is the primary design context. Oye !magine supports:

- English text interaction
- Hindi text interaction in Devanagari
- natural Hinglish input and responses
- English/Hindi CMS localization
- speech-to-text for English, Hindi and Hinglish
- text-to-speech for conversational responses
- explicit microphone consent
- push-to-talk or user-initiated listening by default

The product should translate intent, not words mechanically. Marketing terminology may remain in English where it is clearer.

## 11. Voice interaction

The conversational layer should accept voice wherever the operating context allows it. A user should be able to say, for example, "Mujhe kal ke liye ek reel chahiye, premium lage, zyada salesy nahi" and allow Oye !magine to clarify the outcome, research relevant context, use brand memory, create candidate concepts and take the user to the result.

Voice is an input/output modality over the same permission-aware AI command system. It is not a separate assistant with broader authority.

## 12. Client signup to activation

A new customer journey is state-driven and auditable:

1. User creates the account and workspace.
2. Oye !magine starts private brand discovery and brand-memory creation immediately.
3. The platform researches and generates a world-class preliminary growth plan in the background.
4. The plan remains locked from client delivery while commercial activation is incomplete.
5. KYC is collected and verified.
6. A detailed agreement is generated from an approved Indian legal template, selected modules, commercial terms and scope.
7. The agreement is sent to the authorized client signatory through the configured eSign provider.
8. Once signed, a payment link/mandate is generated.
9. The client chooses monthly or annual recurring billing where the selected plan permits it.
10. Provider webhooks confirm the payment or recurring mandate state idempotently.
11. A tax invoice is generated after successful payment in accordance with the configured finance/tax rules.
12. Only after KYC, signed agreement, successful payment and invoice issuance does the workspace become commercially active.
13. Entitlements for the signed modules become enabled.
14. The previously generated plan and operating tools unlock to the client.
15. Renewal, dunning, failed-payment, suspension, collection and reactivation workflows run automatically.

Provider callbacks, agreement IDs, payment IDs, invoice IDs, mandate IDs and every state transition are evidence-bearing events rather than UI-only statuses.

The legal template itself must be approved and version-controlled by Oye !magine's legal counsel. AI may populate an approved template but does not invent binding legal language silently in production.

## 13. World-class strategy generation

A strategy is never produced from a generic prompt alone. The strategy engine should combine:

- verified brand memory
- client business objective
- product/category economics
- website/catalogue truth
- historic campaign and content outcomes
- search/SEO/SEM signals
- customer and conversion data where connected
- competitor and category research
- current channel capabilities and policies
- Oye platform intelligence patterns
- available budget and approval envelope
- language, geography and audience context

Every strategy receives a strategy version, evidence snapshot, prompt lineage and subsequent outcome linkage so the platform can learn which strategic decisions worked.

## 14. Creative and video intelligence

Images and videos are not treated as disposable files. Each generated asset records concept, prompt lineage, model/provider, reference assets, brand constraints, language, dimensions, channel, objective, audience, product, human edits, approval outcome, publication locations and performance.

The Evolution Engine learns structural patterns such as hook style, composition, copy density, offer placement, duration, CTA, visual treatment, product framing and audience/channel combination. Reuse occurs only at the privacy-safe pattern level unless the asset itself is explicitly reusable.

## 15. Keyword and media intelligence

Keyword, audience and media decisions are measured as learning events. The system learns which search themes, match structures, negatives, copy/keyword combinations, landing pages, bids and audience segments improve qualified outcomes.

Autonomous optimization is allowed only inside the client's approved spend envelope and configured action-delta limits. Increasing the overall financial exposure requires the appropriate authorization.

## 16. Continuous platform improvement

The platform may generate improvement candidates for:

- prompt templates
- provider/model routing
- workflow sequencing
- reusable utilities
- CMS structures
- product guidance
- ranking and retrieval
- evaluation rubrics
- low-risk automation policies
- code changes
- database/schema changes
- guardrail changes

Candidate prompt/routing/workflow improvements can be evaluated and canaried automatically when risk permits. Code, schema, legal and security changes are generated and tested automatically but remain protected by production release gates.

All platform improvement candidates retain test evidence, canary evidence, decision state and rollback history.

## 17. Self-updating utilities and knowledge

Oye !magine continuously refreshes volatile knowledge and connector capabilities through scheduled discovery jobs, provider metadata, official documentation/policy sources, integration health checks, schema inventories and freshness thresholds.

The system distinguishes:

- knowledge refresh
- configuration refresh
- connector capability refresh
- model/provider routing refresh
- application code release
- database migration
- security/legal guardrail change

The first four can be highly automated. The last three require stronger release controls because an autonomous system must not be able to remove its own safety boundary.

## 18. Measurement that drives learning

Learning prioritizes business outcomes. Core signals include CTR, CVR, CPA, ROAS, revenue, engagement, lead quality, approval rate, brand fit, user edit distance, organic visibility, retention, churn, recurring revenue, time-to-publish and experiment lift.

Outcome windows and attribution context are stored so a prompt is not considered "better" merely because it was used more often.

## 19. Anti-overfitting rules

Oye !magine must not mistake coincidence for intelligence. Platform-wide promotion requires adequate sample size, evidence across more than one tenant where applicable, confidence, positive lift, recent evidence and experiment/holdout context where possible.

Patterns can be retired when market behavior changes.

## 20. Failure is also memory

Rejected concepts, bad prompts, poor campaigns, negative feedback, provider errors, policy failures and rollbacks are retained as structured learning signals. The system therefore learns what not to repeat.

## 21. Product language and experience

The interface should feel premium, confident and simple. It should speak in outcomes instead of internal product jargon.

Prefer:

- "Create campaign"
- "Improve this"
- "Why did this change?"
- "Research before deciding"
- "Show me the best option"
- "Take me there"

Avoid exposing unnecessary orchestration language, internal agent names, database terminology or implementation details to normal users.

Advanced operators can inspect evidence, prompt lineage, models, approvals and audit history through expert surfaces.

## 22. Role-aware intelligence

The universal login model remains. The AI search/command layer resolves the signed-in user's membership, tenant, workspace, role, entitlements and assurance level before returning information or executing tools.

A designer, digital marketer, finance approver, partner specialist, client operator and platform owner can ask the same natural-language question but receive different accessible actions according to authority.

## 23. Definition of done for the Evolution Engine

The Evolution Engine is not considered production complete because tables or UI exist. Completion requires:

- migrations applied and schema parity verified
- RLS/revocation/security tests passed
- events emitted from real generation and execution paths
- encrypted prompt lineage verified
- outcomes linked to historical generations
- tenant-private and anonymized-platform reuse tests
- negative cross-tenant access tests
- pattern promotion and retirement tests
- evaluation/canary/rollback proof
- global AI search connected to live CMS/config/workspace data
- English/Hindi/Hinglish interaction tests
- voice provider configured and verified before "live voice" is claimed
- KYC/eSign/payment/invoice provider callbacks verified end to end before commercial activation is claimed
- client entitlement activation proven from a real successful controlled journey
- observability for learning failures, model drift and bad promotion decisions

## 24. Immediate implementation rule

No UI badge, tracker row or marketing sentence may call these capabilities "live", "autonomous", "self-learning" or "production-connected" solely because code exists. Claims advance only with deployment and evidence.

This programme extends the original Oye !magine master scope. It does not replace the security, tenant-isolation, maker-checker, spend-control, privacy, acceptance-test or evidence requirements already defined for the Growth OS.
